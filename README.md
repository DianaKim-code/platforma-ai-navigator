# Платформа — AI‑навигатор

**Текущая версия продукта: MVP v2.**

Статический веб‑прототип бережного AI‑навигатора для женщин 35+. В ветке `agent/interview-informed-navigator` находится кандидат обновления, подготовленный по материалам интервью. Он не опубликован на GitHub Pages и предназначен для локальной продуктовой проверки перед отдельным решением о выпуске.

Навигатор проводит пользователя через семь смысловых блоков:

1. текущая точка;
2. реальный приоритет;
3. конкретная ситуация остановки;
4. зона влияния;
5. последствия, ресурсы и риски;
6. предыдущие решения и помощь;
7. предпочтительный формат поддержки.

Результат содержит текущую точку, главную тему, границы зоны влияния, основные препятствия, один обратимый шаг на 1–3 дня, объяснение логики и подходящий формат поддержки. Навигатор не ставит диагнозов и не рекомендует конкретного специалиста, если данных недостаточно.

## Структура проекта

- `index.html` — интерфейс и стили навигатора.
- `navigator.js` — ветвление, формирование результата, обратная связь и аналитика.
- `specialists.html` — расширяемый каталог специалистов с аналитикой переходов в профиль и WhatsApp.
- `specialist-diana.html` — профиль Дианы в формате будущего каталога специалистов Платформы.
- `expert-diana.jpg` — фотография для карточки рекомендации и страницы профиля.
- `images/hero-platforma.png` — декоративное изображение первого экрана.
- `README.md` — документация проекта.
- `.nojekyll` — отключает обработку Jekyll при публикации статического сайта через GitHub Pages.

## Локальный запуск

Проект не требует сборки и установки зависимостей. Из корня проекта запустите:

```bash
python -m http.server 8000
```

Затем откройте [http://127.0.0.1:8000/](http://127.0.0.1:8000/).

На `localhost` и `127.0.0.1` включён безопасный режим предпросмотра: события и обратная связь складываются в локальный массив `window.__platformaPreviewEvents`, но не отправляются в рабочую Google Таблицу. На опубликованном домене используется действующая интеграция.

Сформированный результат временно сохраняется только в `sessionStorage`, чтобы кнопка браузера «Назад» после просмотра каталога восстановила итоговый экран. Обычный вход на `index.html` показывает первый экран, а новое прохождение удаляет сохранённый результат.

## Публикация через GitHub Pages

Публикация этого кандидата до продуктового подтверждения не выполняется. После подтверждения:

1. проверить и влить согласованную ветку в `main` репозитория `DianaKim-code/platforma-ai-navigator`;
2. открыть **Settings → Pages**;
3. выбрать **Deploy from a branch**;
4. выбрать ветку `main` и папку `/ (root)`;
5. дождаться успешного deployment.

Публичный адрес действующей версии: [https://dianakim-code.github.io/platforma-ai-navigator/](https://dianakim-code.github.io/platforma-ai-navigator/).

## Интеграция с Google Apps Script

На опубликованном домене структурированные события и обратная связь отправляются JSON‑запросами POST в существующий Google Apps Script. Используются действующий `sessionId`, совместимые поля текущей таблицы и тот же endpoint. Открытые ответы основного навигатора не передаются.

Специальный комментарий из формы обратной связи отправляется только после отдельного согласия пользователя. Он записывается в уже поддерживаемое endpoint поле `comment` с пометкой «Открытая обратная связь». Новое неподтверждённое поле схемы не добавляется.

**Не меняйте константу `ENDPOINT` в `navigator.js` без отдельного продуктового и технического решения:** изменение разорвёт действующую интеграцию с Google Таблицей.

## Аналитические события

- `navigator_started`;
- `navigator_step_completed`;
- `navigator_completed`;
- `navigator_result_saved`;
- `navigator_restart_clicked`;
- `support_format_clicked`;
- `specialists_clicked`;
- `profile_whatsapp_clicked`;
- `feedback_started`;
- `feedback_completed`.

События содержат только структурированные технические и продуктовые признаки: `sessionId`, название события, страницу, время, источник, номер шага, маршрут и тип поддержки. Открытые ответы и персональные данные не включаются.

## Проверяемые пользовательские метрики

- старт и завершение навигатора;
- прохождение смысловых блоков и отказы по шагам;
- выбранный структурированный приоритет;
- сформированный маршрут R1–R4;
- тип предложенной поддержки;
- сохранение результата и повторное прохождение;
- интерес к формату помощи и специалистам;
- оценка соответствия результата ситуации;
- ясность первого шага, его реалистичность и понятность объяснения;
- готовность обсудить результат;
- завершение структурированной обратной связи;
- переход в WhatsApp из карточки или профиля специалиста.

## Безопасность

При признаках непосредственной угрозы жизни, насилия, самоповреждения или потребности в срочной медицинской помощи обычный результат и практика не показываются. Пользователь видит отдельный экран с рекомендацией обратиться в местные экстренные службы и к доверенному человеку. Навигатор не ставит медицинских или психиатрических диагнозов.
